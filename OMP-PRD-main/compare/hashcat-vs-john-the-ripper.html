Hashcat vs John the Ripper: Which Cracks Faster?

Hashcat is GPU-first and needs the right mode; John self-detects and ships the *2john extractors. Where each wins, and how to use both together.

Short answer: if you have a GPU and already know which hash mode you are dealing with, Hashcat is the faster tool by a wide margin. If the input is an unusual format, an encrypted file, or a hash you cannot identify, start with John — its *2john extractors and format auto-detection get you to something crackable at all. Most real audits use John to extract and identify, then hand the fast hashes to Hashcat.

Speed: measure it, do not read a blog table

Search this comparison and you will find confident claims — "20x faster", "15–20x", "184,000 H/s for bcrypt". Those numbers describe one GPU, one build and one hash mode on the day somebody ran them. On your hardware they can be wrong by an order of magnitude, and for deliberately slow algorithms the gap between GPU and CPU collapses: bcrypt, scrypt and Argon2 are designed so that parallelism buys you much less.

Measure instead. Two commands, thirty seconds:

hashcat -b -m 1000              # benchmark NTLM on this machine's GPU
john --test=10 --format=nt      # benchmark NTLM on this machine's CPU

Compare the two rates for the mode you actually need, not for MD5. Then decide. The honest rule of thumb: for fast unsalted hashes a GPU runs several times faster than any CPU; for bcrypt-class hashes the difference is small enough that the wordlist and rules matter far more than the tool.

Where John is not optional

Hashcat takes a hash in a documented layout. It does not know how to open an archive, a PDF, a KeePass database or an SSH private key and pull the verifier out of it. John's converters do that:

zip2john backup.zip > backup.hash
john --wordlist=/usr/share/wordlists/rockyou.txt backup.hash

Even when you plan to crack on the GPU, the usual path is: convert with *2john, load the file to confirm the format, then move the fast ones to Hashcat. Refusing to install John because "Hashcat is faster" is how people end up unable to start.

Where Hashcat is not optional

Rule-based mutation is Hashcat's home turf. A base wordlist plus a rule file tests far more realistic password shapes per second than raw brute force, and the rule files are portable and well documented. Its mask engine is also faster and more expressive, and every mode has a canonical example you can copy — hashcat --example-hashes — which removes most of the "wrong format" pain.

A workflow that uses both

  1. Identify. john --list=formats | grep -i <pattern>, or paste the string into a hash identifier. Knowing the algorithm changes everything downstream.
  2. Extract. If the input is a file, run the matching *2john converter. If it is a raw hash, check the layout against --example-hashes.
  3. Benchmark. Run both hashcat -b -m <mode> and john --test=10 --format=<fmt> and use whichever is faster for that hash.
  4. Attack with a plan. Wordlist plus rules first, masks second, brute force last. Switching tools will not save you from a bad candidate set.
  5. Record. --show on both sides, then turn the recovery rate into a policy finding: which accounts failed within an hour.

Frequently asked

Is Hashcat always faster?

No. It is faster when a GPU is available and the hash is fast to compute. For slow, memory-hard algorithms the gap narrows sharply, and for a hash format only John supports, the speed question is moot.

Can John use my GPU?

Partially, through OpenCL in some jumbo builds, but it is not the tool's design centre. If GPU throughput is the goal, that is Hashcat's job.

Can Hashcat read *2john output?

Often yes, once you know the matching mode — but the layouts differ, and converter output sometimes carries fields a mode rejects. Load it in John first to confirm the format, then move it.

Which is easier for a beginner?

John: point it at a file and it usually works out the format. Hashcat asks you to look up a mode number first, which is a real hurdle — the --example-hashes list is the fastest way over it.

Authorised testing only. Both tools are for auditing hashes you own or have written permission to test. Running them against credentials that are not yours is a crime in most jurisdictions, not a hobby.
