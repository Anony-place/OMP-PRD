SpiderFoot

Automate OSINT collection across 200+ modules from one web UI or CLI, with a 37-rule correlation engine that links findings into a graph. Free and open source.

Overview

SpiderFoot is an OSINT automation platform: instead of running ten recon tools by hand, you give it one identifier — a domain, IP, hostname, email, phone number, username, person’s name, ASN, network subnet or a Bitcoin address — and its 200+ modules pull from threat feeds, search engines, DNS records, breach data and social sources for you. Every module publishes what it finds and other modules subscribe to those results, so one seed fans out into an interconnected map of the target’s footprint. What you get at the end is a correlated, browsable report instead of a pile of disconnected rows.

Web UI and CLI on one engine

SpiderFoot ships as a self-hosted web app — python3 ./sf.py -l 127.0.0.1:5001 starts the interface — and the same engine drives a full command-line mode for scripted recon. Because everything runs on your own machine, the targets you investigate never leave your infrastructure. In client work that matters: the tooling itself does not phone home with what you are scanning.

Correlation engine — 37 rules that connect the dots

The 4.0 release added a YAML-configurable correlation engine with 37 pre-defined rules. Where a plain data dump gives you rows, the correlator flags relationships: a breached email tied to a domain reused as a password-reset address, lookalike domains registered in the same week through the same registrar, that class of pattern. Each rule is a small, readable YAML file, so teams can write their own and tune what counts as signal.

Modules, exports and integrations

Modules come in passive flavours (third-party data, no contact with the target) and active ones that probe the target directly — a run is only as intrusive as the modules you enable. Results export to CSV, JSON and GEXF, with a SQLite back-end underneath for custom queries. Tor integration reaches dark-web sources, a Dockerfile covers container installs, and SpiderFoot can call companion tools like DNSTwist, Whatweb, Nmap and CMSeeK mid-scan so their findings land in the same graph.

Offensive and defensive recon

The project is explicit about both sides: run it in an authorized assessment to expand a seed into the target’s real attack surface, or defensively to see what your own organization has exposed — the forgotten staging host, the leaked credentials, the executive’s reused email. MIT-licensed and developed openly since 2012, it remains one of the most complete free recon automation platforms you can self-host.

Key features

  • 200+ modules — threat feeds, DNS, breaches, search engines, social
  • One seed in, correlated graph and browsable report out
  • YAML correlation engine with 37 pre-defined rules (4.0)
  • Web UI and full CLI: sf.py -s example.com -t DOMAIN_NAME -m all
  • CSV, JSON and GEXF export; SQLite back-end for custom queries
  • Tor integration, Dockerfile, calls DNSTwist/Whatweb/Nmap/CMSeeK
  • Self-hosted — your targets never leave your infrastructure
  • Free and open source (MIT), developed since 2012

Install & first run

  1. Install the stable release (Python 3.7+): download the v4.0 archive and run pip3 install -r requirements.txt — or clone master for newer modules (bleeding edge, less tested).
  2. Start the web interface: python3 ./sf.py -l 127.0.0.1:5001.
  3. Open the UI, create a scan, enter the target and pick modules — or keep the defaults for a broad first sweep.
  4. Prefer the terminal: sf.py -s example.com -t DOMAIN_NAME -m all -o tab prints tab-separated findings you can pipe into notes or a pipeline.
  5. Scope every scan to assets you own or are authorized to test, and check which modules run before pointing active ones at production.

Real-world example

All you have is a suspicious domain from a phishing email. Create a SpiderFoot scan with that domain as the seed and let its modules work: DNS records, certificate logs, breach data, threat feeds and similar-domain searches run automatically and link into one graph.

Read the graph outward from the seed. A cluster of lookalike domains registered the same week through the same registrar is a campaign, not a coincidence — export the report and hand the indicator list to your blocking and takedown process.

Common questions

Is SpiderFoot free?

Yes — free and open source under the MIT license, self-hosted on your own machine. No account and no cloud dependency in the open-source release.

Is a SpiderFoot scan passive?

It depends on the modules you enable. Passive modules only query third-party sources and never touch the target; active modules probe it directly (port scanning and similar). Review the module list before a run, and keep it passive-only while you are in the quiet, early phase of an engagement.

How many modules does it have, and do they need API keys?

Over 200. Many passive modules work with no key at all; modules backed by third-party data services add depth when you plug credentials in. SpiderFoot exports and imports your key set, so configuring a fresh install is a one-time job.

What does the correlation engine actually do?

It watches the findings flowing between modules and fires rules over them — 37 rules ship with 4.0, each a small YAML file. Instead of you noticing that one email appears in three separate results, the engine flags the relationship and writes it into the report as a correlation. The format is documented and readable, so custom rules are realistic, not a research project.

Can I run a scan from the command line?

Yes: sf.py -s example.com -t DOMAIN_NAME -m all -o tab runs headlessly (output formats: tab, CSV, JSON), which is how you put recon on a schedule. The web UI is better for exploring results; the CLI is better for pipelines.

What kinds of targets can it take?

Ten entity types: IP addresses, domains and sub-domains, hostnames, network subnets (CIDR), ASNs, email addresses, phone numbers, usernames, person’s names and Bitcoin addresses. Modules subscribe to the entity types they consume, so a single email can fan out into domains, accounts and breach records automatically.

SpiderFoot or theHarvester — which one?

theHarvester is a passive collector: one command, a flat list of emails, subdomains and hosts. SpiderFoot is an automation platform: hundreds of modules feeding each other, correlation, and a browsable entity graph. Use theHarvester for the first hour of recon and SpiderFoot when the investigation needs a map. Both are free and self-hosted.
