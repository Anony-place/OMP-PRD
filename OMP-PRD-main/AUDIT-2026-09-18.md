# OopsMyPassword Production Audit — 2026-09-18

Scope: GitHub application code, admin article/PDF pipeline, Supabase schema/RLS/Storage, public article/product generation, and Firebase deployment workflow.

## Fixed in this audit

- PDF.js browser extraction now configures the matching PDF.js worker.
- PDF imports now extract selectable text into the article body.
- PDF pages are rendered to JPEGs and included in article Markdown so page visuals are preserved.
- Article save rollback now cleans the PDF object and generated page images on every failed save path, including validation/import failures.
- Uploaded media records now carry article_id; new article inserts request the created ID so bookkeeping is linked to the article.
- Live Supabase schema was reconciled with non-destructive created_by and media.article_id columns.
- Anonymous contact-message inserts are restricted to name, email, and message, with length checks.
- Anonymous access to profiles and media was removed.
- Text upload MIME types were aligned with the Storage bucket's allowed MIME types.
- Static SEO generation now renders Markdown images, including the page images produced by PDF imports.
- Firebase deploy workflow now cancels stale in-progress runs for the same ref, preventing an older commit from releasing after a newer commit.
- Supabase bookkeeping rows that were proven to be unreferenced were removed.

## Live findings

- articles bucket: public read, 25 MB limit, PDF/DOC/DOCX/Markdown/Text plus PNG/JPEG allowed.
- Four article rows currently exist; their document_url values were null during the audit.
- The previously observed PDF Storage object was not present when checked; its orphan media row was removed.
- The older DOCX Storage object was still present but unreferenced; its media row was removed. It must be deleted through the Supabase Storage API or Storage UI rather than by deleting storage.objects rows directly.
- Supabase has four published article rows and one published product row used by the static SEO build.
- Live RLS keeps article/product reads public only where intended and admin writes authenticated/admin-gated.

## Remaining non-blocking items

- The legacy articles.author_id column remains alongside the reconciled created_by column. No destructive migration was performed.
- The products table still contains compatibility columns (name/title, product_type/type) with synchronization triggers. This is deliberate compatibility debt, not an immediate runtime failure.
- Contact-form rate limiting is still client-side/cosmetic; server-side abuse throttling remains a separate hardening item.
- Existing Storage objects should periodically be reconciled against DB references using the official Storage API.

## Deployment verification

The latest successful pre-audit deployment pipeline built four article pages and one product page and passed sitemap, QA, and SEO checks. Subsequent audit commits are triggering the same production pipeline with the new fixes.
