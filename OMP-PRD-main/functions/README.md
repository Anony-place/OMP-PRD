# OMP Firebase Cloud Functions

This directory contains Firebase Cloud Functions for OopsMyPassword.

## Functions

### `sitemap`

- **Endpoint**: `/sitemap.xml` (Hosting rewrite → this function)
- **Purpose**: serves the **dynamic** sitemap on the site's own domain
- **Method**: `GET` / `HEAD` (anything else → 405)
- **Response**: `application/xml; charset=utf-8`

**This function is a bridge, not the generator.** The sitemap content is
produced by the Supabase Edge Function `supabase/functions/sitemap` — see
[`../supabase/functions/README.md`](../supabase/functions/README.md) for the
full architecture, deployment and verification steps.

Resolution order (reported back in the `X-Sitemap-State` response header):

| State | Meaning |
|---|---|
| `edge` | served straight from the Supabase Edge Function (normal path) |
| `rest-fallback` | Edge Function unreachable → this function queried Supabase REST itself |
| `static-fallback` | database unreachable → static-route-only sitemap (still valid XML) |

A 404 or a 500 at `/sitemap.xml` is therefore always a deploy problem, never
a data problem.

Firebase Hosting serves a committed static file *before* it evaluates
function rewrites. `firebase.json` therefore **ignores** `sitemap.xml` from
the Hosting upload so the rewrite can actually run. The committed
`sitemap.xml` is a build-time snapshot (generated by `tools/build.py`) kept
for local testing and as documentation of the static route set.

## Security

- **No service-role key anywhere.** Only the publishable (anon) key is used;
  row-level security on Supabase is what keeps drafts out of the sitemap.
- All values are XML-escaped and slug-charset-checked by the shared core, so
  a hostile database row cannot inject markup into the sitemap.
- Slug validation happens *before* any URL is built.
- Errors are logged, never returned to the caller.

## Setup

### 1. Install dependencies

```bash
cd functions
npm install
```

### 2. Point the bridge at the Edge Function

```bash
firebase functions:config:set sitemap.edge_url="https://aeehfulikupskyrvcpzb.supabase.co/functions/v1/sitemap"
```

(or export `SITEMAP_EDGE_URL` before deploying — see `.env.example`)

### 3. Sync the shared core

```bash
npm run sync:sitemap      # runs automatically on `npm run deploy` (predeploy)
```

### 4. Deploy functions **and** hosting

```bash
firebase deploy --only functions,hosting
```

## Testing

```bash
firebase emulators:start --only functions
curl -sD - http://localhost:5001/password-e9a30/us-central1/sitemap | head
```

From the repo root:

```bash
NODE_PATH=./node_modules node tools/test_sitemap.js
```

The local Hosting router used by `tools/test_runtime.js` /
`tools/smoke_all_pages.js` treats `/sitemap.xml` as a function rewrite and
falls back to the committed XML snapshot (Cloud Functions are not running in
those tests).
