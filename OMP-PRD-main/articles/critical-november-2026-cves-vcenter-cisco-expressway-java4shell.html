Critical November 2026 CVEs: VMware vCenter (CVE-2026-123890), Cisco Expressway & Java4Shell

When multiple CVSS 9.8 remote flaws drop alongside active zero-day exploitation and JVM memory corruption bugs, teams need exact version targets and clear remediation sequencing rather than noisy alert dashboards.

1. VMware vCenter Server zero-day (CVE-2026-123890)

Disclosed under Broadcom advisory VMSA-2026-0009 (KB463116), CVE-2026-123890 is an unauthenticated authentication bypass inside the VMware Directory Service (vmdir). Threat intelligence teams observed active zero-day exploitation by state-nexus operators (tracked as ARMORY CASTLE) prior to patch availability.

  • Why vCenter compromises cascade: Reaching control-plane vmdir privileges effectively hands an adversary hypervisor management across every connected ESXi host, VM snapshot, and backup volume.
  • Hardening beyond patching: vCenter management interfaces must never be directly routable from the public internet or standard user VLANs—enforce bastion/ZTNA isolation as outlined in our Secure Remote Access guide.

2. Cisco Expressway clustering RCE (CVE-2026-76466)

CVE-2026-76466 hits clustered deployments of Cisco Expressway-C and internet-facing Expressway-E collaboration gateways. Persistent cookies combined with improper client-certificate validation in the clustering database service enable an unauthenticated attacker with network reachability to run arbitrary OS commands as root.

  • Scope check: Standalone (unclustered) Expressway appliances are not affected, but clustered systems on X15.5.3 and earlier are vulnerable. Older X14 branches have no patch on-branch and require upgrading to X15.5.20 or newer.
  • Active exploitation: Listed in CISA KEV following confirmed field exploitation—audit management ACLs and rotate any credentials resident on exposed Expressway-E edges after upgrading.

3. OpenJDK "Java4Shell" Base64 intrinsic flaw (CVE-2026-114938)

Uncovered on November 17, 2026, CVE-2026-114938 impacts java.util.Base64.Decoder on x86-64 CPUs supporting AVX-512 VBMI instructions across OpenJDK, Oracle Java SE, and GraalVM (17.0.6+, 21, 25, and 27). An integer underflow in HotSpot's hardware-accelerated Base64 intrinsic allows crafted Base64 inputs—common in JWT tokens, API headers, and file parsers—to overwrite heap memory.

How to inventory fast: Use an up-to-date Software Bill of Materials (SBOM) across containers and CI builds to locate every JRE/JDK base image still running pre-November 17 patch levels, and verify Base64/JWT edge inputs with our offline Hash & JWT Inspector. Remember why CVSS severity is not risk: public exposure + active KEV status determines patch order every single time.
