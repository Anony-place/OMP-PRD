Security & Responsible Disclosure

How OMP approaches its own security, and how to report a problem safely.

Architecture choices that shrink risk

  • Static, client-side site. No server-side application logic, no database, no session tokens, no auth surface to attack.
  • Passwords are never sent. All analysis runs in browser JavaScript; there is no endpoint that accepts a password.
  • No third-party scripts. Styles, fonts (system stack), and scripts are first-party, which removes supply-chain and tracking surface.
  • Safe DOM handling. Dynamic UI uses textContent, never innerHTML, for anything influenced by input. No eval() anywhere.
  • CSPRNG-only generation. crypto.getRandomValues() with rejection sampling and a secure shuffle.

Reporting a vulnerability

If you believe you've found a security issue in OMP — for example a way input could be exfiltrated, an XSS, or a generation flaw — email security@oopsmypassword.com with:

  • A description, affected page(s), and reproduction steps.
  • Never real credentials. Use synthetic example passwords in reports.

We ask that you give us reasonable time to fix issues before public disclosure and avoid accessing or modifying other people's data. We do not currently run a paid bug-bounty program, and we won't claim otherwise — accurate credit is happily given if you want it.

Verify our claims

Open your browser's developer tools → Network tab → use the checker. You should see zero requests containing your input. That's the whole design.

Our promises

  • No passwords in logs, URLs, storage, or analytics
  • No eval(), no dynamic remote code
  • Labeled demos, honest estimates
  • Disclosure inbox monitored
