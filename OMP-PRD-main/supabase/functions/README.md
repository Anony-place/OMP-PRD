# OMP — Supabase Edge Functions

Server-side code that runs on Supabase (Deno), not on Firebase.

This directory is **never deployed to Firebase Hosting** — `firebase.json`
ignores `supabase/**`.

## `sitemap`

The **dynamic** `/sitemap.xml`.

| | |
|---|---|
| Source | `supabase/functions/sitemap/index.ts` (+ the shared `sitemap-core.mjs`) |
| Public URL | `https://oopsmypassword.web.app/sitemap.xml` (via the Firebase proxy below) |
| Direct URL | `https://aeehfulikupskyrvcpzb.supabase.co/functions/v1/sitemap` |
| Methods | `GET`, `HEAD`, `OPTIONS` (anything else → 405) |
| Content-Type | `application/xml; charset=utf-8` |
| Cache | `public, max-age=300, stale-while-revalidate=86400` (60s when degraded) |
| Auth | publishable (anon) key only — **never** the service-role key |

### Why an Edge Function and not the committed `sitemap.xml`

The committed `/sitemap.xml` is generated by `tools/build.py` and is a
**static snapshot**: it can only ever list the pages that exist at build
time, so every article and product published from `/admin/` was missing
from it, and `<lastmod>` was frozen at the build date for every URL.

The Edge Function queries `articles` and `products` on every request:

- published rows only (RLS enforces it; the function filters as well),
- `lastmod` = `published_at` → `updated_at` → `created_at` per row,
- static routes keep a fixed build stamp so they don't look "changed daily",
- invalid slugs are dropped, everything is XML-escaped, URLs are de-duplicated.

### How it reaches `/sitemap.xml`

Firebase Hosting can only rewrite a path to a static file or to one of its
own Cloud Functions — it cannot proxy an external URL. So:

```
GET /sitemap.xml
  → Firebase Hosting rewrite  (firebase.json)
  → functions/index.js  `sitemap`  (thin proxy, no secret logic)
  → Supabase Edge Function  (builds the XML)
```

`firebase.json` lists `sitemap.xml` in `hosting.ignore` so the committed
snapshot cannot shadow the rewrite.

If the Edge Function is unreachable, the Firebase function falls back to
querying Supabase REST itself using the same shared core, and finally to a
static-routes-only sitemap. **`/sitemap.xml` never 404s and never 500s.**
The response carries an `X-Sitemap-State` header (`edge` /
`rest-fallback` / `static-fallback` / `degraded` / `fallback`) so you can
see which path served a request.

### Deploy

```bash
# once
supabase login
supabase link --project-ref aeehfulikupskyrvcpzb

# deploy the function
supabase functions deploy sitemap --project-ref aeehfulikupskyrvcpzb

# then make sure hosting + the bridge function are live
cd functions && npm ci && npm run sync:sitemap && cd ..
firebase deploy --only functions,hosting
```

### Configuration (Supabase secrets)

```bash
supabase secrets set SITE_ORIGIN=https://oopsmypassword.web.app \
  STATIC_LASTMOD=2026-08-23 \
  SITEMAP_ALLOWED_ORIGINS=https://oopsmypassword.web.app,https://password-e9a30.web.app \
  --project-ref aeehfulikupskyrvcpzb
```

`SUPABASE_URL` and `SUPABASE_ANON_KEY` are injected automatically by the
runtime — do not set them by hand.

### Test locally

```bash
supabase functions serve sitemap --env-file supabase/functions/.env.local
curl -s http://localhost:54321/functions/v1/sitemap | head
curl -s 'http://localhost:54321/functions/v1/sitemap?format=json'
```

### Verify in production

```bash
curl -sD - https://oopsmypassword.web.app/sitemap.xml -o /tmp/sitemap.xml | grep -i 'x-sitemap-state\|content-type'
grep -c '<loc>' /tmp/sitemap.xml          # should include the live articles/products
grep -c '/products/' /tmp/sitemap.xml     # at least 1 (the live product)
```

## Shared core

`supabase/functions/sitemap/sitemap-core.mjs` holds the route list, the XML
builder and the safety rules. It is plain ESM JavaScript (no `Deno.*`, no
`Node.*`) so it can be:

- imported by the Edge Function (`index.ts`),
- imported by the Firebase fallback (`functions/sitemap-core.mjs`, a synced
  copy — `cd functions && npm run sync:sitemap`),
- imported by the Node test suite (`tools/test_sitemap.js`),
- parsed by `tools/build.py` for the static snapshot's route list.

`tools/test_sitemap.js` fails if the two copies ever diverge, and
`functions/package.json` runs `sync:sitemap` on `predeploy` so a deploy can
never ship a stale copy.
