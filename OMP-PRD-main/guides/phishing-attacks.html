How Phishing Attacks Steal Passwords

The anatomy of modern phishing — lookalike domains, urgency scripts, OAuth consent tricks and MFA-relay proxies — and the defenses that actually work.

Threats 7 min read Updated 2026-08-23
On this page

  • Tactics you will actually see
  • When phishers beat 2FA
  • How to spot them
  • Defenses that work

Phishing works because it attacks people, not systems. It is also the number-one way passwords are stolen — far ahead of brute force. Understanding the playbook makes you dramatically harder to catch.

The anatomy of a phish

  1. Bait: an email/SMS/DM that looks like a service you use — a login alert, a delivery, an invoice, a shared document.
  2. Hook: a link to a pixel-perfect replica login page on an attacker's domain.
  3. Harvest: whatever you type is captured and used within minutes, often by bots.

Tactics you will actually see

  • Lookalike domains: paypa1.com, micros0ft-support.net, or a trusted domain as a subdomain: github.com.verify-account.io.
  • Urgency and fear: "your account will be suspended", "unusual sign-in detected".
  • OAuth consent phishing: instead of a fake password page, a real login page for a malicious app asking for mailbox/drive permissions.
  • QR-code phishing ("quishing") that moves you from a work machine to your less-protected phone.
  • Search ads and malvertising putting fake login pages above the real result.

When phishers beat 2FA

Attacker-in-the-middle proxies relay the real login page live: you enter your password and TOTP code, the proxy forwards them instantly, and the attacker rides the authenticated session. Only origin-bound credentials — hardware keys and passkeys — break this, because the signature simply will not validate for the wrong domain.

How to spot them

  • Check the actual domain — the last two labels before the path, character by character.
  • Be suspicious of any message that wants action right now.
  • Did autofill offer your password? A password manager that goes quiet on a "familiar" login page is sounding an alarm.
  • Unexpected OAuth prompts: read the permissions; a "documents" add-on does not need to read all your mail.

Defenses that work

  1. Navigate manually (bookmark or type the domain) for anything involving credentials.
  2. Password manager autofill as a tripwire — no fill, no typing.
  3. Passkeys / hardware keys — structural immunity to credential phishing.
  4. Slow down on urgency — real providers do not mind you taking five minutes to verify.

If you already clicked

Change the password immediately (from the real site), sign out all sessions, check forwarding rules and recovery settings the attacker may have altered, and watch the account for days. If you reused that password anywhere, change those too — then fix reuse permanently with a manager.

Put it into practice: run your next password through the local checker — it never leaves your browser.
