# Batch-21 — External links open in a new tab (site rule) (2026-11-18)

**User rule:** "jb hum link click krte hai to dusre tab pr open hoga… same tab pr nhi — ye
rule apne site pr hai." → Every EXTERNAL link (official site / GitHub / Docs / content
links to other domains) opens in a NEW TAB (`target="_blank" rel="noopener noreferrer"`).
Internal links (relative paths + our own hosts) keep normal same-tab navigation.

## Implementation (4 layers, all idempotent)

1. **`scripts/lib/external-links.mjs`** (new) — `externalizeHtml()`: external `<a>` gets
   `target="_blank"` + `rel="noopener noreferrer"` (merged if rel already present).
   Skips: existing `target=`, non-http(s) hrefs, internal hosts (`oopsmypassword|omp-prd`),
   and **JSON-LD `<script>` blocks** (FAQ text can embed anchors — regex must never break
   the JSON). 8 node unit tests + 6 python twin tests pass.
2. **`scripts/build-static-seo.mjs`** — `writeFile` wrapped: every generated .html
   (articles, products, osint/pentest tool pages, hubs) passes through `externalizeHtml`.
3. **`scripts/build-phase3-seo.mjs`** — `fs.writeFileSync` wrapped for .html writes
   (compare, glossary, cheatsheets, dork-builder/hash-inspector/url-scanner, sitemap.html).
4. **`tools/omp_build/layout.py`** — `page()` returns `externalize_html(html)` (python twin).
   Plus **runtime net in `assets/js/main.js`** for dynamically-injected markup.

Known-good emitters already had `target="_blank"` (footer Instagram, hub tile links); the
tool-page buttons ("Open official site →" / "GitHub" / "Docs") and markdown-rendered
content links only had `rel` — those were the same-tab offenders.
