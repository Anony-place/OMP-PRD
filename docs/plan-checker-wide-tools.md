## Part 1 — The wide password-checker layout (UI/UX fix)

### Audit (why it looks cramped today)

| Surface | Wrapper | Effective width | Problem |
| --- | --- | --- | --- |
| Home (`index.html#checker`) | right column of `.hero-grid` (`1.02fr .98fr`, gap 56px) | ~540–580px of the 1180px container | checker squeezed beside hero copy; stats 2×2 tiny; analysis/recommendations stack into one long column |
| `/checker` page | `.container-narrow` (860px, centered) | 860px | better, but still one narrow column |

Relevant CSS: `--maxw: 1180px`, `.container-wide` (1400px) **already exists unused**;
`.analysis-panel` is a single-column grid (Analysis stacked above Recommendations);
`.stat-grid` is 2×2. Breakpoints already in place: 1060px (hero stacks), 860px,
640px (score row stacks), 380px.

### Verdict on "layout pura wide ho jana chahiye?"

**Yes — but not by stretching one column.** Full-width single column just makes
long text lines and a stretched input. The professional pattern is a **wide
dashboard**: one wide section, with the interior split into responsive columns
so desktop space is actually used.

### Proposed design (Option A — recommended)

1. **Home:** move the checker OUT of the hero-grid into its own full-width band
   directly under the hero (keep `id="checker"` — hero CTA and mobile menu link
   to `/#checker`; those anchors must keep working). Hero becomes a centered
   single-column: chip + h1 + lead + 2 CTAs + trust chips.
2. **Checker interior (shared component, new modifier class e.g.
   `.checker-card--wide`):**
   - Row 1: password input full width + privacy note
   - Row 2: score + meter + strength pill (fixed ~340px) │ stat tiles
     (4-across ≥1060px, 2×2 below)
   - Row 3: **Analysis │ Recommendations side-by-side** (2 columns)
   - ≤860px: everything stacks (existing mobile behaviour preserved)
3. **`/checker` page parity:** drop the `container-narrow` squeeze, use the same
   wide component. The body is generated by `OMP-PRD-main/tools/omp_build/pages_core.py`
   (`checker_body`) — **HTML + generator parity is mandatory** (standing rule).
4. **Scoring logic untouched** — `checker.js`, entropy/crack estimates and the
   analysis copy stay exactly as they are. This is layout only.

### Options considered and rejected

| Option | Why not |
| --- | --- |
| B — expand-to-wide on first keystroke | layout shift while typing (CLS/jank), stateful CSS, fragile on mobile |
| C — only rebalance hero columns (wider right column) | still cramped; hero copy gets squeezed instead |

### Risks / checks in the implementation PR

- `#checker` anchor + `data-checker-context="home"/"page"` both keep working
- width regression guard: container stays 1180px (earlier accepted decision:
  **never shrink the container** — this change only widens the checker block)
- run `tools/qa.py`, `scripts/verify-seo.mjs`, node tests from `OMP-PRD-main` cwd
- mobile screenshot pass at 380/640/860/1060px

**Effort:** small-medium (CSS + small markup move + generator parity), 1 PR.

## Part 2 — New tool features ("what is my ip" etc.)

### What already exists (inventory, no duplicates needed)

13 live surfaces: checker, generator, breach-check, password-health, passphrase,
entropy, random-string, security-checklist, dork-builder, hash-inspector
(SHA-256/512 + hash ID + JWT + Base64/Hex), url-scanner, compare, tools hub.
New features should be a **new category: network/privacy utilities** — that is
the gap.

### Demand evidence (suggestqueries probes, this session)

| Cluster | Autocomplete | SERP reality | Verdict |
| --- | --- | --- | --- |
| `what is my ip` | 10 variants (`address`, `location`, `ipv4`, `vpn`, `nordvpn`, `on my phone/computer`) | Google answers the IP **inline in the SERP** (zero-click) + whatismyip.com / Cloudflare giants | Don't fight the head term; build the tool and win the long-tails |
| `ip leak` | 10 variants (`test`, `check`, `checker`, `detector`, `online`, `website`) | ipleak.net, browserleaks — niche sites, not DR-80 giants | **WIN-able + perfectly on-brand** (privacy) |
| `dns leak test` | 10 variants (nordvpn, surfshark, mullvad, cloudflare…) | same niche incumbents | fold into the same page — the VPN crowd searches both |
| `random password generator` | 10 variants (`free`, `12/15 characters`, `easy to remember`, `with special characters`) | we already have `/generator` | **SEO language pass on the existing page — no new build** |
| `whois lookup` | 10 variants | GoDaddy/ICANN giants | P2, needs an RDAP feasibility spike |
| ssl checker / remote scanners | — | — | **SKIP** — needs a server-side fetch; breaks the client-side brand and the zero-budget rule |

### Recommended build: ONE feature page, "sessions separated" inside

**`/ip-check` — "What Is My IP Address? IPv4/IPv6 + VPN Leak Check"** with four
separated sub-tool sections (this matches the "session separated" idea):

1. **Public IP (IPv4/IPv6)** — via one free disclosed endpoint (ipify / Cloudflare
   trace). Honest banner: "this page contacts X to show your public IP — that
   request is what reveals it". The site's "no fake tools, no fake stats" rule
   demands this disclosure.
2. **WebRTC leak check** — pure client-side `RTCPeerConnection` candidate
   inspection (local vs STUN-derived addresses).
3. **DNS resolver identity** — DoH TXT `whoami` (e.g. whoami.ds.akahelp.net over
   cloudflare-dns.com) — "which resolver actually sees your lookups".
4. **Timezone/language vs IP-country mismatch** — a simple privacy tell.

Explicitly out of scope (and said so on the page): full DNS-leak test (needs
authoritative NS logs — link out honestly to the specialist sites), IP
geolocation maps, whois.

**Feasibility spike (first task after approval, before any page build):** confirm
CORS + no-key access on the chosen endpoints (ipify, Cloudflare DoH, trace
endpoint). Fallback endpoints pre-listed. If the spike fails, the batch still ships
Part 1.
