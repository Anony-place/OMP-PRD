# Search Console read — 1–7 November 2026

First real Performance export for `https://oopsmypassword.vercel.app` (7 days,
web search only, no filters). It answers the one question the audit could not:
**is the site invisible because it is broken, or because nobody is searching
for what it sells?**

Short answer: it is not broken. It has almost no demand, with one loud
exception — and that exception is the plan.

---

## 1. The headline numbers

| Metric | Value |
| --- | --- |
| Clicks | **5** |
| Impressions | **846** (chart) / 860 (sum of pages) |
| CTR | **0.59 %** |
| Average position | **32.5** |

Daily impressions: 36 → 122 → 160 → 109 → 179 → **240**. That is 6.7× in six
days, and it is real: the two spikes in the query report are dated dorks that
landed on 1 Nov and 5 Nov, and neither day spikes.

## 2. Three things that look like problems and are not

**The host split is not live.** The repository says `web.app` in 225 files, but
`vercel-build.sh` rewrites the origin at deploy time. Checked directly on
2026-11-09: live `robots.txt` advertises four `vercel.app` sitemaps and names the
`vercel.app` property; live `sitemap.txt` is 100 % `vercel.app`. The `web.app`
Search Console property fails its sitemap fetches **because `web.app` is a 301
host** — correct behaviour. `docs/audit-response-2026-11.md` carries the
correction.

**The "top page" is a robot.** 62 impressions come from one `site:`-chained
dork, twice, at position 1.0 — an audit tool crawling us. That single query
pushed `/articles/malware-families-explained` (89 impressions, position 1.81)
and `/learning/.../malware-families` (74 impressions, position 1.0) to the top of
the report with **zero clicks**. Position 1 with 0 clicks out of 1.0 is not a
page; it is a crawler. Those two URLs are 19 % of the week's impressions and
100 % of it is fake. Every future read must subtract this.

**Search Console will not show a quarter of the data.** Visible queries account
for 394 impressions against 860 on pages — **54 % of impressions are
anonymised.** Query-level conclusions here are directional only.

## 3. What is actually happening

The distribution is the story:

| Section | Impressions | Share | Clicks |
| --- | --- | --- | --- |
| `/articles` | 295 | 34.3 % | 3 |
| `/learning` | 262 | 30.5 % | 1 |
| `/glossary` | 101 | 11.7 % | **0** |
| `/cheatsheets` | 73 | 8.5 % | **0** |
| `/osint` | 41 | 4.8 % | **0** |
| `/compare` | 32 | 3.7 % | **0** |
| `/pentest` | 34 | 4.0 % | 1 |
| **All 11 tools + homepage** | **20** | **2.3 %** | **0** |

- **The homepage has zero impressions.** Not a penalty, not a canonical problem
  — nothing on it answers a query anybody types.
- **The product is 2.3 % of the traffic.** Eleven tools, twenty impressions in a
  week. `/breach-check` 6, `/entropy` 5, `/dork-builder` 4, `/url-scanner` 1,
  `/security-checklist` 1. When a tool does surface it ranks well —
  `/dork-builder` at position 7.0, `/url-scanner` at 4.0, `/entropy` at 13.2 —
  so the pages are fine; nothing points at them and nothing searches for them.
- **The glossary is dead weight.** 101 impressions at average positions 46–100
  and zero clicks. A 140-word definition page cannot rank against NIST, OWASP
  and Investopedia, and it never will at any length we would realistically write.
- **`/learning` soaks up 30 % of impressions and returns one click**, and its
  dozens of position-40–90 pages drag the site average down to 32.5. No more
  investment there (the remap idea stays dropped).
- **`/compare` already ranks on page one** — `shodan-vs-censys` at 5.93,
  `amass-vs-subfinder` at 7.0, `bitwarden-vs-proton-pass` at 10.0 — and gets
  zero clicks on 32 impressions. Cheap to improve, low ceiling.

### The one page that works

`/articles/john-the-ripper-no-password-hashes-loaded`: **63 impressions, 7.3 % of
the site's total, position 5.3, 1 click.** Its query cluster is nine spellings of
the same sentence — `john the ripper no password hashes loaded` (21 impressions,
5.33), `… (see faq)` (3, 6.0), `no password hashes loaded` (1, 3.0),
`using default input encoding: utf-8 no password hashes loaded (see faq)` (2,
4.0) — **33 impressions, positions 3–10, 0 clicks.**

That is the entire evidence base for the strategy, and it is enough: one page
written for one sentence a person actually types beats 190 pages written for
keywords nobody types.

### Why the other error page got nothing

`/articles/hashcat-token-length-exception` — published 2026-11-05, **0
impressions.** Its title is the name of the exception hashcat prints
(*"Hashcat Token Length Exception: Every Cause, One Fix"*). Autocomplete for the
sentence people actually type returns:

> `hashcat no hashes loaded` → `hashcat no hashes loaded token length exception`,
> `hashcat salt-value exception no hashes loaded`, `hashcat says no hashes loaded`

The exception name is a **sub-variant of the query**, not the query. Two to four
days of data is too early to call it dead, but the targeting is inverted and that
is fixable today.

> **Rule for the engine: the title is the sentence the user types, never the
> string the tool prints.**

### On CTR: not yet a workstream

Roughly 140 impressions arrived at positions 5–12 with zero clicks. At normal
position-8 CTR that predicts ~2.5 clicks, so zero is unlucky but not impossible
(≈8 %). With five clicks in the whole week the sample cannot separate a genuine
CTR problem from noise. It becomes a workstream when a **single page** passes
~300 impressions in a window. Until then do not rewrite titles for CTR.

## 5. What changed in the plan

| Was | Now | Why |
| --- | --- | --- |
| P0 host flip = the fix that caps growth | **Hygiene only** — repo consistency, retire the `web.app` property | Production already canonicalises to `vercel.app` |
| P1 discoverability: ship "Eleven tools" and traffic follows | **Do it, but as conversion and internal linking, not as a traffic lever** | Homepage has 0 impressions; the grid cannot create demand |
| P3 error pages, 2 per week | **P3 promoted to P0** — the only measured demand engine, batch-published, volume-verified first | `john` is 7.3 % of all impressions from 1 of 199 pages |
| P4 fatten glossary 140 → 350 words | **Dropped** | 101 impressions at positions 46–100, zero clicks |
| P4 fatten compare pages | **Keep, last** — they rank page one already, so the gain is small | `shodan-vs-censys` 5.93 but only 15 impressions |
| — | **New: every page that already receives impressions gets repaired before new pages are written** | 42 impressions already land on a cheat sheet with visible defects |

## 6. The batch this justifies

One PR. Three new pages, one retarget, two repairs — every item backed by data
above, none of it speculative.

**New — all with 10-variant autocomplete tails**

1. `/articles/bitwarden-autofill-not-working` — the largest cluster found, and
   on-brand; cross-links the existing `bitwarden-not-syncing`.
2. `/articles/burp-suite-browser-not-launching` — embedded Chromium on Linux,
   the `--no-sandbox` and missing-library causes, per-platform fixes.
3. `/articles/metasploit-database-not-connected` — `msfdb init`, the
   `pg_ctl`/socket path causes, `db_nmap` and workspace failures.

**Retarget — not a rewrite**

4. `hashcat-token-length-exception` → `/articles/hashcat-no-hashes-loaded`,
   positioned on the sentence users type, with token-length and salt-value as the
   causes underneath it.

**Repair — pages already receiving impressions**

5. `/cheatsheets/incident-response-first-hour-cheatsheet` — 42 impressions at
   position 8.19, zero clicks; the rendered list double-numbers (`1. 1.`) and a
   shell checklist carries an irrelevant *Wordlist Path* field.
6. `/breach-check` — the query `k anonymity password check` (7 impressions,
   position 69.7) lands on `/glossary/k-anonymity` (position 62.4) and the
   glossary is the wrong page. The tool does the range-query the query is asking
   about; it should own the phrase.

## 7. How we will know it worked

Checked on the next export, no window changes:

| Signal | Today | Target |
| --- | --- | --- |
| Clicks per week | 5 | **≥ 25** within 21 days |
| Impressions per week | 846 | ≥ 2 500 |
| Pages receiving ≥10 impressions | 10 | ≥ 25 |
| Any single page past 300 impressions | 0 | 1 (the first real CTR measurement) |
| `web.app` impressions | 0 | stays 0 — the property is deleted |

Stop rule: if three pages published under this rule each fail to pass **10
impressions in 14 days**, the error-string hypothesis is falsified and the next
move is backlinks and tool-directory listings, not more articles.
