# Batch 14 — CVSS Score Calculator (2026-11-17)

**Goal:** own the "cvss score calculator" + "cvss 3.1 calculator" intent (15 imp @91 in the
11-17 GSC export) with a client-side tool that also serves the "cvss 3.1 vs 4.0" comparison
surface — the gap no competitor closed (mlab.sh has the biggest tool footprint; cve.tools has
a calculator; nobody had the worked example + calculator pair).

## What shipped

1. **`/cvss-calculator`** — standalone tool page in the url-scanner style (hero, tool surface,
   disclosure band, 5 FAQs, related links).
2. **`assets/js/cvss-calculator.js`** — the exact CVSS v3.1 specification, client-side:
   - Base score (Exploitability = 8.22 × AV × AC × PR × UI; Impact per scope; Roundup at 1e-5),
   - Temporal and Environmental (modified metrics with the X = clean-metric fallback),
   - Vector parser accepting CVSS:3.1 / 3.0 / 4.0 strings,
   - Severity bands per the spec rounding table.
   - **v4.0 = decode only** — metric-by-metric decode + bands, no invented score. The page says
     to use the FIRST reference implementation for a v4.0 number.
3. **Wiring:** layout.py (15th tool + target icon), pages_core.py ("Fifteen tools" counts,
   Scanning & OSINT group), sitemap-core.mjs ×2 (+1 URL → 220), build-phase3-seo.mjs (mobile
   menu, footer Tools column, llms.txt entry), test_mobile_ux.mjs (15 slugs, "Fifteen").
4. **Functional test** in test_tools_live.mjs: jsdom drives the calculator — the unauth RCE
   vector must score 9.8, the XSS vector 6.1, and a v4.0 vector must open the decoder
   (macrovector explanation) instead of faking a score. 56/56 pass.
5. **DB:** `articles/cvss-score-explained` gained an inline CTA to /cvss-calculator after the
   worked example (REPLACE, has_cta=true).

## Engine verification (node, module.exports)

All 9 reference vectors pass: 10.0 (S:C Log4Shell shape), 9.8 (S:U RCE), 6.1 (XSS S:C),
7.8 (local privesc), 4.8 (AC:H MITM shape), 8.8 (adjacent), temporal 8.0, temporal 9.0,
environmental 10.0. Two "failures" during development were wrong test expectations, not
engine bugs (4.8 vs 5.9 hand-calc; 8.0 vs 8.1 roundup of 7.958) — the engine matched the
hand-calculation both times.

## Pipeline lesson (important)

`python3 tools/build.py` alone is **not** enough after registry changes — its footer/head
template is stale (drops tool links, removes the RSS link). The correct local pipeline is
`python3 tools/build.py && node scripts/build-phase3-seo.mjs` (phase-3 restores the final
footer/heads and regenerates the sitemaps). Running build.py alone produced a regression
footprint that phase-3 healed; the final diff is registry-driven only (sitemap delta = exactly
+1 URL).
