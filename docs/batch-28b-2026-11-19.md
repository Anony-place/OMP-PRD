## Root cause (from the check-run annotations API)

```
SEO regression: articles/secure-remote-access.html: broken internal link
-> /learning/cyber-security/cyber-security-track/secure-remote-access
```

Batch-28's See-also edit linked the "secure remote access learning track" URL
that the 11-19 deep read had pulled from GSC queries (24 impressions @ 71.8).
But that URL is **not a page**: the learning track was migrated into
`/articles/*` and `/glossary/*` long ago; `vercel.json` carries 301s for the
migrated twins (malware-families, data-classification, common-crypto-failures,
...) and a catch-all `/learning/:path* -> /articles`. The deep read's advice to
"interlink with the learning-track page" was wrong — the twins are redirect
sources, and linking a redirect source both trips the link gate and wastes
signal.

(Second casualty of the same model: the salary article's GSC URL in the deep
read, `cyber-security-salary-in-usa-2026-bls-o-net-role-experience-bands`, is a
misparse. The real slug is `cyber-security-salary-in-usa-complete-guide-to-
cybersecurity-salaries-in-2026`; the meta_title/meta_description landed on the
right row.)

## Pipeline knowledge (correcting the session model)

- **`publish-content.yml`** ("content: publish from panel") is the *panel*
  pipeline: repository_dispatch from the admin panel, or the 15-min cron that
  promotes scheduled rows. It builds DB pages, gates (verify-seo + tests),
  commits generated paths as `omp-bot`, pushes, and polls the live host.
- **`firebase-static-hosting.yml`** runs on EVERY push to main: full build from
  the live DB + the whole gate suite + Firebase deploy. This is how merged DB
  edits go live; its verify gate is what caught the broken link.
- The failed run's numbers (annotation): `static=33 guides=15 articles=48
  products=2 sitemap_urls=229`. The articles table has **48 rows** (the audit's
